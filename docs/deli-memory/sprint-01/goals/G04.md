# G04 — Onboarding
Sprint 1 | Worktree: `cd-onboarding` | Branch: `feat/g04-onboarding`
Bloqueio: nenhum (independente) | Estimativa: 3 dias

---

## Objetivo

Todo novo cliente tem playbook de onboarding D1/D7/D30/D60/D90 ativado automaticamente na assinatura do contrato. Consultor acompanha progresso em UI dedicada. Task Trigger.dev dispara ações automáticas nos marcos (WhatsApp de acompanhamento, alertas internos).

---

## Sub-goals

### G04.1 — Migration `onboarding_checklists`

```
/goal
Branch: feat/g04-onboarding | Worktree: ~/worktrees/cd-onboarding

Criar migration supabase/migrations/20260525_004_onboarding.sql:

CREATE TABLE onboarding_templates (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid REFERENCES tenants(id),
  marco text NOT NULL CHECK (marco IN ('D1','D7','D30','D60','D90')),
  titulo text NOT NULL,
  descricao text NOT NULL,
  acao_automatica text,
  active boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE onboarding_checklists (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants(id),
  customer_id uuid REFERENCES customers(id),
  contrato_id uuid REFERENCES contratos(id),
  marco text NOT NULL CHECK (marco IN ('D1','D7','D30','D60','D90')),
  status text NOT NULL DEFAULT 'pendente' CHECK (status IN ('pendente','em_andamento','concluido')),
  concluido_em timestamptz,
  notas text,
  agendado_para date,
  created_at timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE onboarding_checklists ENABLE ROW LEVEL SECURITY;
ALTER TABLE onboarding_templates ENABLE ROW LEVEL SECURITY;
CREATE POLICY "tenant_own" ON onboarding_checklists FOR ALL
  USING (tenant_id=(SELECT tenant_id FROM profiles WHERE id=auth.uid()));
CREATE POLICY "tenant_see_own_or_global" ON onboarding_templates FOR SELECT
  USING (tenant_id IS NULL OR tenant_id=(SELECT tenant_id FROM profiles WHERE id=auth.uid()));

Seed templates globais:
- D1: "Configuração inicial" — verificar acesso ao painel + grupos WhatsApp
- D7: "Primeira semana" — revisar primeiros resultados iFood
- D30: "Primeiro mês" — análise de métricas + ajustes
- D60: "Dois meses" — review de estratégia
- D90: "Trimestre" — renovação / upsell

Smoke: SELECT COUNT(*) FROM onboarding_templates → 5.
OUTPUT BRUTO: resultado do SELECT.
```

### G04.3 — Task `onboarding-automacao`

```
/goal
Branch: feat/g04-onboarding

Criar trigger/onboarding/automacao.ts:
- task id="onboarding-criar-checklist" (chamada por G03.4 quando contrato assinado)
  InputSchema: { contrato_id: string; customer_id: string; tenant_id: string; vigencia_inicio: string }
  run():
    1. Calcular datas: D1=vigencia_inicio, D7=+7, D30=+30, D60=+60, D90=+90
    2. INSERT INTO onboarding_checklists 5 rows (uma por marco)
    3. logAgentRun

- schedules.task id="onboarding-verificar-marcos" cron="0 9 * * *" (6h BRT)
  run():
    1. Buscar onboarding_checklists WHERE agendado_para=today AND status='pendente'
    2. Para cada item: notificar Eduardo via Bridge /agents/deli/notify (telegram_interno)
       Mensagem: "Onboarding D{marco} do cliente {customer_name} é hoje!"
    3. logAgentRun com { notificacoes: N }

Anti-padrão: notificação ao CLIENTE antes de revisão humana — só telegram_interno.

Smoke: trigger onboarding-criar-checklist com contrato válido → 5 rows em onboarding_checklists.
OUTPUT BRUTO: SELECT COUNT(*) FROM onboarding_checklists WHERE contrato_id=... → 5.
```

## Critério de aceite G04

- [ ] Novo contrato assinado → `onboarding_checklists` com 5 marcos criados automaticamente
- [ ] Consultor vê checklist por cliente na UI `/onboarding`
- [ ] `onboarding-verificar-marcos` roda todo dia em `agent_runs`
- [ ] D7: Eduardo recebe notificação no telegram_interno

---

## Anti-padrões específicos G04

1. Task `onboarding-criar-checklist` enviando WhatsApp direto ao cliente — só criar checklists
2. UI sem paginação — clientes com 49 registros devem ter paginação (pageSize=20)
3. `agendado_para` calculado em UTC em vez de BRT — sempre UTC-3 para datas
4. Marco D90 sem "oportunidade de upsell" nas notas — seed do template deve incluir isso
