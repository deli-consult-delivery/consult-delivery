# G03 — Contratos Digitais
Sprint 1 | Worktree: `cd-contratos` | Branch: `feat/g03-contratos`
Bloqueio: nenhum (independente) | Estimativa: 4 dias

---

## Objetivo

Sistema de contratos digitais: consultor cria contrato no painel, PDF gerado, link enviado ao cliente, cliente assina digitalmente (timestamp + hash), cobrança criada no Asaas automaticamente. Meta: 80% dos 49 clientes com contrato assinado em D30.

---

## Sub-goals

### G03.1 — Migration `contratos`

```
/goal
Branch: feat/g03-contratos | Worktree: ~/worktrees/cd-contratos

Criar migration supabase/migrations/20260525_003_contratos.sql:

CREATE TABLE contratos (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants(id),
  customer_id uuid REFERENCES customers(id),
  pacote text NOT NULL CHECK (pacote IN ('light','performance','enterprise','growth')),
  valor_setup numeric(10,2),
  valor_mensal numeric(10,2) NOT NULL,
  percentual_crescimento numeric(5,2),
  duracao_meses int,
  multa_percentual numeric(5,2),
  status text NOT NULL DEFAULT 'rascunho' CHECK (status IN ('rascunho','enviado','assinado','encerrado')),
  assinado_em timestamptz,
  assinatura_hash text,
  asaas_subscription_id text,
  vigencia_inicio date,
  vigencia_fim date,
  pdf_url text,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE contratos ENABLE ROW LEVEL SECURITY;
CREATE POLICY "tenant_own" ON contratos FOR ALL
  USING (tenant_id=(SELECT tenant_id FROM profiles WHERE id=auth.uid()));

Smoke: SELECT COUNT(*) FROM contratos → 0 (tabela criada).
OUTPUT BRUTO: resultado do SELECT.
```

### G03.3 — Bridge `enviar-assinatura`

```
/goal
Branch: feat/g03-contratos

Criar endpoint no Bridge Server (bridge-server/routes/contratos.ts):
POST /contratos/:id/enviar-assinatura

Fluxo:
1. Buscar contrato no Supabase (verificar tenant via x-tenant-id header)
2. Gerar PDF básico (usar puppeteer ou html-pdf-node — verificar qual está instalado)
3. Upload PDF para Supabase Storage (bucket 'contratos')
4. UPDATE contratos SET pdf_url=..., status='enviado'
5. Enviar WhatsApp via Evolution API com link do PDF
6. Retornar { success: true, pdf_url, whatsapp_sent: true }

Smoke: POST /contratos/:id/enviar-assinatura com contrato de test → contrato.status='enviado' no DB.
OUTPUT BRUTO: curl response JSON + SELECT status FROM contratos WHERE id=...
```

### G03.4 — Bridge `link-asaas` + assinatura digital

```
/goal
Branch: feat/g03-contratos

Criar endpoint no Bridge Server:
POST /contratos/:id/link-asaas
POST /contratos/sign (público, sem auth — cliente assina aqui)

link-asaas:
1. Verificar contrato existe + status ∈ ('enviado','assinado')
2. Chamar Asaas POST /subscriptions com valor_mensal, customer
3. UPDATE contratos SET asaas_subscription_id=..., status='assinado' (se já assinado)
4. Retornar { asaas_subscription_id, asaas_url }

sign (público):
1. Receber { contract_id, ip, user_agent }
2. Gerar hash: SHA256(contract_id + timestamp + ip)
3. UPDATE contratos SET assinado_em=NOW(), assinatura_hash=hash, status='assinado'
4. Disparar Trigger.dev task 'contrato-assinado' (cria onboarding_checklists D1)

Smoke: sign endpoint → SELECT assinado_em, assinatura_hash FROM contratos WHERE id=... (não nulo).
OUTPUT BRUTO: resultado do SELECT.
```

## Critério de aceite G03

- [ ] Consultor cria contrato em UI → `contratos.status='rascunho'` no DB
- [ ] POST enviar-assinatura → `contratos.status='enviado'` + PDF gerado
- [ ] Cliente acessa link → assina → `contratos.status='assinado'` + `assinatura_hash IS NOT NULL`
- [ ] `contratos.asaas_subscription_id` preenchido após G03.4

---

## Anti-padrões específicos G03

1. Cliente assina via endpoint que requer auth — `/contratos/sign` deve ser público (sem token)
2. PDF gerado sem URL pública — usar Supabase Storage com policy de leitura pública
3. Asaas API key hardcoded — usar variável de ambiente via Infisical
4. Onboarding não criado após assinatura — G03.4 deve disparar task para criar D1
